# План: E-commerce платформа

## 1. Общие сведения

- **Цель:** полнофункциональный интернет-магазин с корзиной, фильтрацией, поиском, личным кабинетом и тестовой оплатой.
- **Технологический стек (предлагаемый):**
  - Backend: Node.js + Express (или Python FastAPI)
  - Frontend: React + Vite (SPA) либо SSR (Next.js)
  - БД: PostgreSQL (основная) + Redis (кэш/сессии/корзина)
  - Платёжная интеграция: Stripe в test-режиме (или ЮKassa/Робокасса sandbox)
  - Деплой: Docker Compose
- **Аудитория:** B2C, русскоязычный интерфейс.

---

## 2. Этапы разработки

### Этап 0 — Подготовка (1–2 дня)
- Настройка окружения: Node.js, Docker, PostgreSQL, Redis.
- Инициализация репозитория, структура папок monorepo (`client/`, `server/`, `shared/`).
- CI: базовые линтеры и тесты.
- Соглашения: код-стиль, именование API, git-flow.

### Этап 1 — Бэкенд-ядро (5–7 дней)
- Настройка сервера, роутинг, middleware (CORS, JSON, ошибки).
- Подключение БД через ORM (Prisma / SQLAlchemy).
- Модели данных и миграции (см. раздел 4).
- Базовые CRUD для товаров и категорий.
- Валидация входных данных (zod / pydantic).

### Этап 2 — Каталог и товары (4–5 дней)
- Категории (вложенность до 2 уровней).
- Атрибуты товаров: название, описание, цена, скидка, остаток, изображения, характеристики (JSON).
- API: список с пагинацией, детальная карточка, похожие товары.
- Поиск (полнотекстовый через PostgreSQL FTS или Elasticsearch при росте).
- Фильтрация по цене, категории, атрибутам, наличию, сортировка.

### Этап 3 — Корзина (3–4 дня)
- Корзина на клиенте (localStorage) с синхронизацией на сервер для авторизованных (Redis, TTL 30 дней).
- Операции: добавить, изменить количество, удалить, очистить.
- Пересчёт цен, учёт скидок и остатков на момент оформления.
- Бейдж-счётчик в шапке сайта.

### Этап 4 — Пользователи и личный кабинет (5–6 дней)
- Регистрация / вход: email + пароль, JWT access + refresh.
- Восстановление пароля (email-ссылка, test-режим: логирование ссылки).
- Профиль: ФИО, телефон, адреса доставки (несколько).
- История заказов и статусы.
- Избранное (wishlist).

### Этап 5 — Оформление заказа и платежи (5–6 дней)
- Создание заказа из корзины: данные доставки, способ оплаты.
- Статусная модель заказа: `created → paid → processing → shipped → delivered / cancelled`.
- Интеграция Stripe test mode:
  - checkout session (redirect) ИЛИ Payment Intents (inline);
  - webhook для подтверждения оплаты (idempotency).
- Безопасность: проверка суммы на сервере, лимиты попыток, флаги тест-режима.

### Этап 6 — Админ-панель (5–6 дней)
- Управление товарами, категориями, остатками, заказами.
- Просмотр и смена статусов заказов, подтверждение оплат.
- Базовые роли: admin / user (middleware по ролям).

### Этап 7 — Frontend (8–10 дней, параллельно с этапами 2–5)
- Каркас приложения: роутинг, layout, стейт-менеджер.
- Страницы: главная, каталог, карточка товара, корзина, чекаут, кабинет, заказ, логин/регистрация.
- Компоненты: карточка товара, фильтры, пагинация, поиск-саггест, формы.
- Адаптивность (mobile-first), базовые анимации, UX-состояния (загрузка/пусто/ошибка).

### Этап 8 — Тестирование и QA (3–4 дня)
- Юнит-тесты бэкенда (расчёт цен, фильтры, статусы заказа).
- Интеграционные тесты API.
- E2E-сценарии (Playwright): покупка целиком.
- Тест платёжного флоу в sandbox.

### Этап 9 — Инфраструктура и релиз (2–3 дня)
- Docker Compose: api, db, redis, web, nginx.
- Seed-скрипт с демо-товарами и тестовой картой Stripe (`4242 4242 4242 4242`).
- Мониторинг: логи, healthcheck `/health`.
- Настройка production-переменных (.env, секреты).

## 3. Архитектура

```
Client (React SPA)
   │  REST/JSON + JWT
   ▼
API Server (Express/FastAPI)
   │
   ├── Modules: auth, catalog, cart, orders, payments, admin
   ├── Redis: сессии, корзина, кэш
   └── PostgreSQL: персистентные данные
        ▲
        └── Stripe (test) через webhook/API
```

- Монолит модульной структуры (быстрее старт) → при росте выносить payments/orders в микросервисы.
- Все внешние вызовы (Stripe, email) через интерфейсы для замены тест-провайдеров.

## 4. Модель данных (PostgreSQL)

| Таблица | Ключевые поля |
|---|---|
| `users` | id, email, password_hash, name, phone, role, created_at |
| `addresses` | id, user_id, label, street, city, zip |
| `categories` | id, parent_id, name, slug, position |
| `products` | id, category_id, name, slug, description, price, discount_price, stock, attributes(jsonb), images(jsonb), active |
| `cart_items` | id, user_id, product_id, quantity |
| `orders` | id, user_id, total, status, payment_method, created_at |
| `order_items` | id, order_id, product_id, name_snapshot, price_snapshot, quantity |
| `payments` | id, order_id, provider, provider_ref, amount, status, created_at |
| `wishlist` | id, user_id, product_id |
| `refresh_tokens` | id, user_id, token_hash, expires_at |

Снимки (snapshots) в `order_items` сохраняют цену/название на момент покупки.

## 5. API (REST, префикс `/api/v1`)

- `POST /auth/register`, `POST /auth/login`, `POST /auth/refresh`, `POST /auth/logout`
- `GET /categories`
- `GET /products?search=&category=&minPrice=&maxPrice=&sort=&page=&inStock=`
- `GET /products/:slug`
- `POST /cart`, `PATCH /cart/:productId`, `DELETE /cart/:productId`, `GET /cart`
- `POST /orders`, `GET /orders`, `GET /orders/:id`
- `POST /payments/checkout` → создаёт Stripe Session
- `POST /payments/webhook` — публичный, с проверкой подписи Stripe
- `GET /me`, `PATCH /me`, `POST /me/addresses`
- `GET/POST/DELETE /wishlist`
- Админ: `CRUD /admin/products`, `/admin/categories`, `/admin/orders/:id/status`

Формат ответа: `{ data, meta }` для списков, `{ error, message, details }` для ошибок.

## 6. Безопасность

- Пароли: bcrypt/argon2, JWT с коротким TTL + refresh token.
- HTTPS, CORS белый список, rate limiting (login, checkout, webhook).
- Валидация всех входов, параметризованные запросы (ORM).
- Цены и суммы считаются только на сервере.
- Webhook Stripe: проверка `stripe-signature`.
- Секреты только в `.env`, не в репозитории.
- RLS/роли на уровне API (admin middleware).

## 7. Платёжная интеграция (Stripe test)

1. `POST /payments/checkout` — сервер создаёт Stripe Checkout Session:
   - `mode: payment`, `line_items` из корзины, `success_url`, `cancel_url`.
2. Клиент редиректится на страницу Stripe (test mode).
3. Stripe шлёт webhook `checkout.session.completed`.
4. Webhook помечает `payments.status = succeeded`, `orders.status = paid`, уменьшает остатки.
5. Тестовая карта: `4242 4242 4242 4242`, любой будущий срок, любой CVC.
6. Альтернатива: ЮKassa/Робокасса sandbox — по желанию заказчика.

## 9. Критерии готовности (Definition of Done)

- Регистрация/вход, профиль, адреса — работают.
- Каталог: поиск, фильтры, сортировка, пагинация.
- Корзина: полный цикл добавления → оформления.
- Оплата: тестовая транзакция проходит и статус заказа меняется.
- История заказов в кабинете отображается корректно.
- Админка: управление товарами и заказами.
- Все критичные пути покрыты E2E-тестами.
- Приложение собирается через Docker Compose одной командой.
